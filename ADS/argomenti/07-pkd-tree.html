      Parallel kd-tree

      The Pkd-tree (Men, Shen, Gu, Sun — UC Riverside) is an in-memory spatial tree that is highly parallel, cache-efficient, and dynamic: supporting construction, batch updates, and multi-dimensional queries on a single weight-balanced tree.

      7Katch.github.io/ ADS/ 07 · Pkd-tree

      1. The kd-tree: Fundamentals & Systems Context

      New to kd-trees?

      If you have never encountered spatial trees before, read our beginner guide first: kd-tree da Zero: Guida Visuale & Intuitiva, which explains spatial partitioning, the circle test, and range queries step by step.

      kd-tree Architecture (Bentley, 1975)

      A binary spatial partitioning tree designed to index points in \(D\)-dimensional Euclidean space \(\mathbb{R}^D\). Each internal node signifies an axis-aligned splitting hyperplane \(\langle d, x \rangle\). Points with coordinate value smaller than \(x\) on dimension \(d\) belong to the left subtree, while the remainder fall into the right subtree. The space is partitioned recursively until the cardinality of a sub-space drops to or below the leaf wrap threshold \(\phi\).

      Dimensionality Notation: In this paper, \(D\) explicitly denotes the dimensionality (rather than \(k\)) to avoid confusion with the \(k\) in k-nearest neighbor (\(k\)-NN) queries.

      Splitting Strategy: Widest Stretch vs. Round-Robin

      A fundamental design decision is how to select the splitting dimension \(d\) at each interior node:

      • Classic Round-Robin Cycling (Bentley, 1975): Cycles dimensions in predetermined succession: \(d = (\text{depth} \bmod D) + 1\). If the dataset has disparate variance along different dimensions (e.g. latitude vs. elevation), round-robin forces splits on low-variance axes, yielding elongated, needle-shaped bounding boxes.
      • Widest Dimension / Maximum Spread (Friedman et al., 1977; used in Pkd-tree): Always cuts the dimension with the largest spread: \[ d = \arg\max_{1 \le i \le D} \left( \max_{p \in P} p[i] - \min_{p \in P} p[i] \right) \] This ensures spatial partitions remain roughly hyper-cubical (isotropic), which minimizes the probability that search spheres in \(k\)-NN or bounding rectangles in range queries intersect multiple boundaries.
      The Curse of Dimensionality (\(D \approx 10\))

      The kd-tree is practically unmatched for dimensions up to \(D \approx 10-12\). Why not higher dimensions?

      In high-dimensional space, the ratio of the volume of a hyper-sphere to its bounding hyper-cube shrinks exponentially towards zero. Consequently, a \(k\)-NN search sphere will inevitably intersect almost every axis-aligned partition hyperplane, forcing the search algorithm to backtrack through virtually all branches. At \(D > 15-20\), a kd-tree typically degrades to a brute-force \(O(n)\) linear scan. For \(D \le 10\), however, spatial pruning remains mathematically optimal.

      Systems Insight: The Leaf Wrap Threshold \(\phi\)

      Why do we stop splitting when \(|P| \le \phi\) (where \(\phi\) is a small constant, e.g. 16 to 32) instead of building a tree with single-point leaves?

      • Cacheline Packing: A single point requires its own node object and pointers (16–24 bytes per node). By packing \(\phi\) points into a contiguous leaf array, all points in the leaf fit inside one or two hardware cachelines (\(B = 64\) bytes).
      • Pointer Overhead Elimination: Eliminates \(\approx 50\%\) of the tree's internal nodes, cutting tree pointer traversal and memory footprint in half.
      • SIMD / Vectorized Linear Scan: Once the traversal reaches a leaf, computing Euclidean distance over \(\phi\) continuous coordinates is heavily vectorized using CPU SIMD instructions (AVX-512 / AVX2).

      2. The Problem: Data Scales Up, Existing kd-trees Do Not

      Modern spatial repositories have expanded drastically. For example, the North America dataset of OpenStreetMap comprises over 1.29 billion coordinate nodes. Constructing a kd-tree on this dataset sequentially via CGAL (the industry standard computational geometry library) requires more than 2,000 seconds (over 33 minutes). In an era of multi-core servers, lack of end-to-end parallelism is untenable.

      Systematic Failures in Existing Paradigms

      Existing state-of-the-art implementations exhibit severe structural compromises:

      • Static Implementations (e.g., ParGeo Static): Extremely fast at construction, but strictly read-only. Inserting or deleting data is impossible without a full rebuild.
      • Full Tree Rebuilding (CGAL & ParGeo BHL-tree): Lacks parallel update support. Even in sequential mode, rebalancing an updated tree forces a full structural reconstruction (\(O(n \log n)\) work), causing severe stop-the-world latency spikes.
      • The Logarithmic Method (ParGeo Log-tree, Bentley 1980): Avoids full rebuilds by maintaining a set of \(O(\log n)\) perfectly balanced trees of geometric sizes \(\{2^0, 2^1, 2^2, \dots\}\). While updates are parallelized by cascading merges (analogous to binary addition carries), every single query must traverse all \(O(\log n)\) trees and merge results. As a result, Log-tree is up to 10× slower on \(k\)-NN queries than a single tree.
      • Cache-Inefficient Construction: Existing parallel partition routines incur \(O(\log n)\) independent memory movement passes, falling significantly behind parallel binary search trees and octrees.

      3. The Pkd-tree Architecture & Benchmark Evidence

      Two Foundational Theoretical Breakthroughs

      1) Cache-Optimal Parallel Construction (Chapter 3): Instead of shifting the entire dataset across memory at each individual tree level, Pkd-tree constructs \(\lambda\) levels simultaneously in a single pass of data movement. Partition splitters are calculated using a small sample set, followed by a cache-conscious sieving routine that partitions points into \(2^\lambda\) buckets. By configuring \(\lambda = \Theta(\log M)\), the algorithm achieves simultaneously:

      \[ W = O(n\log n) \qquad Q = O\!\left(\frac{n}{B}\log_M n\right) \qquad S = \text{polylog}(n) \quad \text{whp} \]

      2) Reconstruction-Based Weight-Balanced Updates (Chapter 4): Classic rebalancing primitives—such as tree rotations (AVL/Red-Black) or B-tree node splits/merges—are geometrically impossible in kd-trees without re-sorting points. Pkd-tree enforces weight-balancing with a lazy tolerance parameter \(\alpha\): deviations in subtree weights are tolerated up to factor \(\alpha\). Once violated, only the localized affected subtree is reconstructed in parallel using the fast construction subroutine.

      Single-Tree Query Advantage

      Because the Pkd-tree maintains a single coherent kd-tree at all times, all standard, highly optimized static kd-tree query algorithms run directly without alteration, completely avoiding the multi-tree aggregation bottleneck of the logarithmic method.

      Quantitative Performance Gains (96-core benchmark)

      On \(10^9\) 2D points: Batch Insertion is 2.02–62× faster than Log-tree; Batch Deletion is 3.27–400× faster; and \(k\)-NN queries are 6.71–11.9× faster. Compared to full rebuild implementations (CGAL and BHL-tree), updates are several orders of magnitude faster.

      4. Preliminaries: The Work–Span Model of Parallelism

      Binary Fork-Join Computational Paradigm

      The algorithms are designed and analyzed in the standard shared-memory work-span model with binary forking. Each thread behaves as a sequential RAM augmented with an instruction fork, which creates two child threads executing in parallel. The parent thread suspends until both children synchronize via join. A parallel loop over \(n\) elements is constructed as a balanced binary fork tree with depth \(O(\log n)\). The entire computation is formally modeled as a Directed Acyclic Graph (DAG):

      • Work (\(W\)): The total number of operations executed across all vertices in the DAG. This is equivalent to the algorithm's sequential running time on a single processor.
      • Span (\(S\)): The length of the longest directed path (critical path) within the DAG. It represents the minimum possible execution time on an infinite number of processors.

      Scheduling Theorem (Brent's Lemma & Work-Stealing)

      By Brent's Theorem, any greedy parallel scheduler can execute a computation with work \(W\) and span \(S\) on \(\rho\) processors in time:

      \[ T_\rho \le \frac{W}{\rho} + S \]

      In distributed runtime systems, utilizing a randomized work-stealing scheduler (Blumofe & Leiserson, 1999), idle processors steal tasks from busy processors' double-ended queues. The execution time satisfies:

      \[ T_\rho = \frac{W}{\rho} + O(S) \quad \text{with high probability (whp)} \]

      Algorithmic Consequence: The maximum achievable speedup is bounded by \(\frac{W}{S}\) (the parallelism). To scale near-linearly to massive multi-core systems (\(\rho = 96, 128, \dots\)), the span \(S\) must be strictly polylogarithmic in \(n\) (\(S = O(\log^c n)\)), while work \(W\) must remain optimal.

      5. Preliminaries: The Ideal-Cache Model & Memory Hierarchy

      Two-Level Memory Model (Frigo, Leiserson, Prokop, Ramachandran, 1999)

      To analyze memory traffic independent of specific hardware cache configurations, we adopt the classic ideal-cache model:

      • The memory system consists of two levels: an internal small memory (the cache) of capacity \(M\), and an unbounded external memory (the main memory).
      • Both memories are partitioned into uniform blocks (cache lines) of size \(B\).
      • The CPU can only operate on data residing in cache, with zero access penalty.
      • Accessing data not present in cache triggers a block transfer (cache miss) that loads a block of size \(B\) from main memory at unit cost.
      • The cache complexity \(Q\) is the total number of block transfers executed.

      The Mathematics of Cache Bound: Why \(\log_M n\)?

      Applying the change-of-base logarithmic identity:

      \[ \log_M n = \frac{\log_2 n}{\log_2 M} \]

      The Classical Bottleneck: A standard parallel partitioning routine partitions data 1 level at a time. Across \(\log_2 n\) tree levels, every level performs a full scan over \(n\) points, costing \(O(n/B)\) block transfers per level, culminating in a suboptimal cache complexity of \(O\left(\frac{n}{B}\log_2 n\right)\).

      Pkd-tree's Innovation: Pkd-tree builds \(\lambda = \Theta(\log M)\) tree levels concurrently in a single data movement pass. Once a subproblem fits into cache size \(M\), all subsequent internal splits occur with zero additional block transfers. The total number of memory passes is reduced from \(\log_2 n\) to:

      \[ \frac{\log_2 n}{\lambda} = \frac{\log_2 n}{\Theta(\log_2 M)} = O(\log_M n) \implies Q = O\!\left(\frac{n}{B}\log_M n\right) \]

      Theoretical vs. Real-World Caches: Sleator-Tarjan Competitive Ratio

      The ideal-cache model assumes an optimal offline replacement policy (Belady's MIN algorithm). Is this realistic for practical hardware? Yes!

      By the seminal Sleator-Tarjan theorem (1985), an online Least Recently Used (LRU) or First-In-First-Out (FIFO) cache with capacity \(2M\) incurs at most twice the number of cache misses as an optimal offline cache of capacity \(M\). Asymptotically, hardware LRU caches preserve the theoretical bounds.

      6. Formal Specifications & Weight-Balancing Mathematics

      Formal Splitters and Tree Representation

      Points reside in \(\mathbb{R}^D\), and distances are Euclidean \(\|p - q\|_2 = \sqrt{\sum_{i=1}^D (p[i] - q[i])^2}\). An axis-aligned partition hyperplane is defined by a splitter tuple \(\langle d, x \rangle\), where \(1 \le d \le D\) is the split dimension and \(x \in \mathbb{R}\) is the coordinate threshold.

      Every interior node \(T\) stores:

      • Splitter definition \(\langle d, x \rangle\).
      • Subtree pointers \(T.lc\) (points with \(p[d] < x\)) and \(T.rc\) (points with \(p[d] \ge x\)).
      • Subtree weight \(|T|\): the total number of points contained in subtree \(T\).
      The 3 Query Workloads: Formal Formulation
      • k-Nearest Neighbors (k-NN): Given a query point \(q \in \mathbb{R}^D\), retrieve the set \(K \subset P\) such that \(|K| = k\) and \(\forall p \in K, \forall p' \in P \setminus K : \|p - q\|_2 \le \|p' - q\|_2\).
      • Orthogonal Range Report: Given an axis-aligned bounding hyper-rectangle \(R = \prod_{i=1}^D [l_i, u_i]\), return all points \(p \in P\) such that \(l_i \le p[i] \le u_i\) for all \(1 \le i \le D\).
      • Orthogonal Range Count: Return the cardinality \(|\{p \in P \mid p \in R\}|\).
        Subtree Weight Pruning: Because each node stores its weight \(|T|\), if a node's bounding box is strictly enclosed within \(R\), the algorithm directly adds \(|T|\) in \(O(1)\) time without exploring the subtree!
      Weight-Balance Formalism & Height Theorem

      Given the balancing parameter \(\alpha \in [0, 0.5]\), a kd-tree subtree \(T\) is weight-balanced if and only if:

      \[ 0.5 - \alpha \;\le\; \frac{|T.lc|}{|T|} \;\le\; 0.5 + \alpha \]

      Height Bound Proof: In any weight-balanced tree, each child contains at most \((0.5 + \alpha)|T|\) points. Therefore, for an arbitrary path from root to leaf in a tree of size \(n\), the depth \(h\) satisfies:

      \[ n \cdot (0.5 + \alpha)^h \ge 1 \implies h \le \frac{\log n}{\log \left(\frac{1}{0.5 + \alpha}\right)} = O(\log n) \]

      For example, with \(\alpha = 0.2\), each branch retains at most \(70\%\) of the points, yielding a bounded maximum height of \(h \le \frac{\log_2 n}{\log_2(1/0.7)} \approx 1.94 \log_2 n\).

      Why Weight-Balance Instead of Height-Balance?

      Classic balanced trees (such as AVL or Red-Black trees) maintain height balance via local rotations. In a spatial kd-tree, however, rotating two nodes changes the coordinate cut dimensions, scrambling the geometric space and requiring full point re-evaluation.

      Instead, weight-balancing directly controls the exact number of points in each subproblem. This enables a lazy rebalancing strategy: when an update unbalances a subtree, the cost of rebuilding it in parallel is strictly proportional to the number of points it contains, allowing amortized analysis (Overmars' reconstruction theorem) to prove optimal update bounds.
